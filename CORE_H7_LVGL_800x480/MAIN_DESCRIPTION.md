### Константы

```c
#define QSPI_BUFF_SIZE    100                    // Размер буфера QSPI (не используется)

#define LVGL_BUF_SIZE     (PIXELS_W * LVGL_BUF_LINES)  // = 1024 * 60 = 61440 пикселей
```

Из `main.h`:
```c
#define PIXELS_H  600    // Высота дисплея в пикселях
#define PIXELS_W  1024   // Ширина дисплея в пикселях
```

### Буферы LVGL

```c
static lv_color_t buf1[LVGL_BUF_SIZE];  // Буфер 1 для LVGL (~120 КБ)
static lv_color_t buf2[LVGL_BUF_SIZE];  // Буфер 2 для LVGL (~120 КБ)
```

**Зачем два буфера:** Пока LVGL рисует в один буфер, DMA2D копирует содержимое другого буфера на экран. Это называется **двойная буферизация** — повышает производительность, т.к. рисование и вывод на экран идут параллельно.

Буферы находятся во внутренней RAM (AXI SRAM по адресу 0x24000000), потому что она быстрее внешней SDRAM.

### Буфер BMP

```c
static uint8_t BMP_BUFF[1152000] __attribute__((section(".extram")));
```

Большой буфер (1.1 МБ) во внешней SDRAM для хранения BMP-изображений. Атрибут `__attribute__((section(".extram")))` говорит линкеру поместить его в секцию внешней SDRAM, а не во внутреннюю RAM.

### `Color_To_565()` — строка 112

```c
uint16_t Color_To_565(uint8_t r, uint8_t g, uint8_t b)
{
    return ((r & 0xF8) << 8) | ((g & 0xFC) << 3) | ((b & 0xF8) >> 3);
}
```

**Что делает:** Конвертирует цвет из формата RGB888 (по 8 бит на канал) в формат RGB565 (16 бит).

**Как работает RGB565:**
```
Бит:  15 14 13 12 11 | 10 9 8 7 6 | 5 4 3 2 0
       R  R  R  R  R |  G G G G G | B B B B B
       5 бит красный | 6 бит зелёный | 5 бит синий
```

- `r & 0xF8` — берёт старшие 5 бит красного
- `g & 0xFC` — берёт старшие 6 бит зелёного
- `b & 0xF8` — берёт старшие 5 бит синего

Формат RGB565 занимает 2 байта вместо 3, что экономит память и увеличивает скорость отрисовки. Для дисплея 1024x600 один кадр = 1 228 800 байт (вместо 1 843 200 при RGB888).

**Где используется:** В данный момент не вызывается из кода, но может понадобиться при ручной работе с пикселями.

### `my_disp_flush()` — строка 117

```c
void my_disp_flush(lv_disp_drv_t * disp, const lv_area_t * area, lv_color_t * color_p)
{
    while(DMA2D->CR & DMA2D_CR_START) {}
    uint32_t size = (area->x2 - area->x1 + 1) * (area->y2 - area->y1 + 1) * 2;
    SCB_CleanDCache_by_Addr((uint32_t *)color_p, size);
    LTDC_Color_Fill(area->x1, area->y1, area->x2, area->y2, (uint16_t *)color_p);
    lv_disp_flush_ready(disp);
}
```

**Что делает:** Это **callback** (функция обратного вызова), которую LVGL вызывает каждый раз, когда нарисовал кусок интерфейса и хочет отправить его на дисплей.

**Параметры:**
- `disp` — указатель на драйвер дисплея LVGL
- `area` — прямоугольная область экрана (x1, y1, x2, y2), которую нужно обновить
- `color_p` — указатель на буфер с готовыми пикселями

**Пошагово:**

1. **`while(DMA2D->CR & DMA2D_CR_START) {}`**
   Ждёт, пока предыдущая операция DMA2D не завершится. Бит `START` в регистре CR сбрасывается аппаратно, когда DMA2D закончил работу.

2. **`SCB_CleanDCache_by_Addr()`**
   Сбрасывает D-Cache для области буфера. Это **критически важно**: процессор пишет пиксели через кэш, а DMA2D читает напрямую из RAM. Без сброса кэша DMA2D может прочитать устаревшие данные → артефакты на экране.

3. **`LTDC_Color_Fill()`**
   Запускает DMA2D для копирования пикселей из буфера LVGL в фреймбуфер (SDRAM по адресу 0xC0000000). Копирование идёт аппаратно — процессор свободен.

4. **`lv_disp_flush_ready(disp)`**
   Сообщает LVGL, что вывод завершён и можно рисовать следующий фрагмент.

**Закомментированная версия (строки 127–140):**
Простая реализация через `memcpy` — копирует пиксели построчно программно. Работает, но намного медленнее, чем DMA2D.

### `my_touchpad_read()` — строка 141

```c
void my_touchpad_read(lv_indev_drv_t * indev_drv, lv_indev_data_t * data)
{
    if(TouchIRQFlag) {
        TouchIRQFlag = 0;
        TouchCount = GT911_ReadTouch(&GT911Touch[0]);
    }
    if(TouchCount) {
        data->state = LV_INDEV_STATE_PRESSED;
        data->point.x = GT911Touch[0].XCoordinate;
        data->point.y = GT911Touch[0].YCoordinate;
    } else {
        data->state = LV_INDEV_STATE_RELEASED;
    }
}
```

**Что делает:** Callback для LVGL — вызывается каждые 15 мс для проверки, есть ли касание экрана.

**Пошагово:**

1. Проверяет флаг `TouchIRQFlag`. Этот флаг устанавливается в `1` обработчиком прерывания `EXTI3_IRQHandler()`, когда тачскрин GT911 сигнализирует о касании.

2. Если флаг установлен — сбрасывает его и читает данные касания через I2C (`GT911_ReadTouch()`). Функция возвращает количество касаний (0–5).

3. Если есть хотя бы одно касание — передаёт LVGL координаты **первого** касания (мультитач не используется). Состояние = `PRESSED`.

4. Если касаний нет — состояние = `RELEASED`.

**Почему используется флаг, а не чтение напрямую:** Чтение по I2C — медленная операция. Если читать каждые 15 мс без проверки, процессор будет тратить время впустую. Прерывание позволяет читать данные только когда палец реально на экране.

### `EXTI3_IRQHandler()` — строка 155

```c
void EXTI3_IRQHandler(void)
{
    LL_EXTI_ClearFlag_0_31(GT911_INT_Pin);
    NVIC_ClearPendingIRQ(EXTI3_IRQn);
    TouchIRQFlag = 1;
}
```

**Что делает:** Обработчик прерывания от пина PE3 (GT911_INT). Вызывается аппаратно при касании экрана.

**Пошагово:**
1. Очищает флаг прерывания EXTI (иначе прерывание будет вызываться бесконечно)
2. Очищает ожидающее прерывание в NVIC
3. Устанавливает флаг `TouchIRQFlag = 1`, который потом проверяется в `my_touchpad_read()`

**Важно:** Обработчик прерывания должен быть максимально коротким. Здесь нет чтения I2C — только установка флага. Чтение данных происходит позже, в основном цикле программы.

### `main()` — строка 471 — ТОЧКА ВХОДА

Это первая функция, вызываемая после стартового кода. Выполняется один раз при включении/перезагрузке.

```
Порядок инициализации:
━━━━━━━━━━━━━━━━━━━━━

1. Включение кэшей процессора
   ├─ SCB_EnableICache()    — кэш инструкций (ускоряет чтение кода из Flash)
   └─ SCB_EnableDCache()    — кэш данных (ускоряет чтение/запись RAM)

2. HAL_Init()               — инициализация HAL: SysTick на 1 мс, приоритеты прерываний

3. SystemClock_Config()      — настройка тактирования (PLL → 480 МГц)

4. Инициализация периферии (сгенерировано CubeMX):
   ├─ MX_GPIO_Init()        — все пины ввода/вывода
   ├─ MX_FMC_Init()         — контроллер внешней памяти (SDRAM)
   ├─ MX_I2C4_Init()        — шина I2C для тачскрина
   ├─ MX_LTDC_Init()        — LCD-контроллер
   └─ MX_DMA2D_Init()       — 2D-ускоритель графики

5. Пользовательская инициализация:
   ├─ SDRAM_InitSequence()   — последовательность команд для запуска SDRAM
   ├─ LTDC_Init()            — инициализация слоя дисплея, очистка экрана
   └─ GT911_Init()           — инициализация тачскрина GT911

6. Инициализация LVGL:
   ├─ lv_init()                          — запуск ядра LVGL
   ├─ lv_disp_draw_buf_init()           — привязка буферов buf1/buf2
   ├─ Регистрация драйвера дисплея:
   │   ├─ flush_cb = my_disp_flush      — как выводить пиксели
   │   ├─ hor_res = 1024, ver_res = 600 — разрешение
   │   └─ lv_disp_drv_register()        — зарегистрировать
   └─ Регистрация драйвера ввода:
       ├─ type = POINTER                — тип: указатель (тач)
       ├─ read_cb = my_touchpad_read    — как читать касание
       └─ lv_indev_drv_register()       — зарегистрировать

7. Создание UI:
   └─ lv_demo_widgets()     — стандартное демо LVGL
       // tabview() — закомментировано (пользовательский UI)
       // lv_example_meter_my() — закомментировано
       // lv_example_get_started_my() — закомментировано

8. Бесконечный цикл:
   └─ while(1) {
        idle_time = lv_timer_handler();  — обработка всех задач LVGL
        HAL_Delay(idle_time);            — спать, пока нечего делать
      }
```

#### Бесконечный цикл (строки 547–557)

```c
while (1)
{
    uint32_t idle_time = lv_timer_handler();
    if(idle_time > 0) HAL_Delay(idle_time);
}
```

**`lv_timer_handler()`** — основная функция LVGL. При каждом вызове:
- Проверяет, нужно ли перерисовать что-то на экране
- Если нужно — рисует изменённые области (не весь экран!) в буфер и вызывает `my_disp_flush()`
- Проверяет ввод (вызывает `my_touchpad_read()`)
- Обрабатывает анимации и таймеры
- Возвращает время (мс) до следующего нужного вызова

**`HAL_Delay(idle_time)`** — усыпляет процессор на `idle_time` мс. Экономит энергию — процессор не крутится вхолостую.

### `SystemClock_Config()` — строка 565

**Сгенерирована CubeMX. Не редактировать вручную.**

Настраивает систему тактирования MCU:

```
HSI (64 МГц внутренний RC-генератор)
  │
  ▼
PLL1 (PLLM=4, PLLN=60, PLLP=2)
  │
  ├─ SYSCLK = HSI/4 * 60 / 2 = 480 МГц
  │
  ├─ AHB = SYSCLK / 2 = 240 МГц
  │
  ├─ APB1 = AHB / 2 = 120 МГц
  ├─ APB2 = AHB / 2 = 120 МГц
  ├─ APB3 = AHB / 2 = 120 МГц
  └─ APB4 = AHB / 2 = 120 МГц
```

- Режим питания: `PWR_REGULATOR_VOLTAGE_SCALE0` — максимальная производительность
- Источник: HSI (High Speed Internal) — не требует внешнего кварца
- Flash Latency: 4 — задержка чтения Flash при высокой частоте

### `Error_Handler()` — строка 628

```c
void Error_Handler(void)
{
    __disable_irq();
    while (1) {}
}
```

Вызывается при критической ошибке HAL. Отключает все прерывания и зависает навсегда. В реальном продукте здесь стоит добавить:

## Блоки USER CODE — что это и зачем

CubeMX генерирует код с блоками вида:
```c
/* USER CODE BEGIN xxx */
  ...ваш код здесь...
/* USER CODE END xxx */
```

**Правило:** Весь ваш код должен быть **только внутри** этих блоков. При перегенерации кода через CubeMX всё, что **вне** блоков USER CODE, будет перезаписано. Содержимое внутри блоков сохраняется.

Основные блоки в main.c:
| Блок | Где | Что там размещать |
|---|---|---|
| `USER CODE BEGIN Includes` | После #include | Ваши #include |
| `USER CODE BEGIN PV` | Переменные | Ваши глобальные переменные |
| `USER CODE BEGIN 0` | Перед main() | Ваши функции |
| `USER CODE BEGIN 2` | В main(), после инициализации | Ваш код инициализации |
| `USER CODE BEGIN WHILE` | В while(1) | Ваш основной цикл |
| `USER CODE BEGIN 3` | После while(1) | Код после цикла (обычно пусто) |
| `USER CODE BEGIN 4` | После main() | Дополнительные функции |
